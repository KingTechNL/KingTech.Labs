# Cloudflare Tunnels
Cloudflare Tunnel is a secure outbound connector that creates an encrypted path from your private network to Cloudflare without opening inbound ports on your firewall. Instead of exposing services directly to the internet, your self-hosted apps stay internal and are published through Cloudflare, where you can apply DNS, access policies, and Zero Trust controls. In this guide, the tunnel runs inside an LXC container on Proxmox to provide reliable, authenticated access to homelab services.


## Creating a Cloudflare Tunnel container in a Proxmox cluster using LXC:
The steps below describe how to set up a Cloudflare Tunnel container using a Linux container in Proxmox.
These steps where executed on our [MLab mini rack](../../Projects/MLabMiniRack/index.mdx) cluster.

### Step 1: Download Ubuntu LXC Template
If you don't have the LXC template for Ubuntu 24.04 yet, you need to download it first by following these steps.
 1. Log into your Proxmox web UI.
 1. Select your target Node in the left-hand Datacenter menu.
 1. Click on your storage (usually named `local`).
 1. Go to the **CT Templates** tab.
 1. Click **Templates**.
 1. Select the operating system or turnkey appliance you want, in our case this is `Ubuntu 24.04`, then click **Download**.

### Step 2: Create the LXC Container
We create a stock Ubuntu 24.04 LXC container we can use to install Cloudflare WARP.
 1. Log into your Proxmox web UI.
 1. Click Create CT in the top right corner.
 1. Keep Unprivileged container checked (enabled)
 1. On the next tab, select the `Ubuntu 24.04` template.
 1. On the next tab, assign 6GB of disk to the container. *(Between 4GB and 8GB is recommended)*
 1. On the next tab, we need to select **1** as the amount of CPU cores.
 1. On the next tab, select 128 MB RAM and 128 MB Swap. 
 1. On the next tab, we select the following network settings:
    * **Bridge:** Must be `vmbr0` (or whichever standard bridge name exists and is identical on all cluster nodes).
    * **VLAN Tag:** Leave blank (unless your cluster uses a specific management or traffic VLAN).
    * **IPv4:** Select Static.
    * **IPv4/CIDR:** Assign a static IP (e.g., `192.168.1.77/24`). Do not use DHCP, as other devices or apps need a fixed address to connect to this WARP gateway.
    * **Gateway (IPv4):** Enter your main local router IP (e.g., `192.168.1.1`).
 1. On the next tab, leave the DNS settings empty. This will make it use the host settings.
 1. On the next tab, select `Start after created`  click finish.

### Step 3: Install the Cloudflare Tunnel client
 1. Go to the [Tunnels page](https://dash.cloudflare.com/?to=/:account/tunnels) for your cloudflare account.
 1. Select **Create Tunnel**.
 1. Enter a name for your tunnel (for example: `MLAB-1`).
 1. Select **Create Tunnel**.
 1. Under **Setup Environment**, select `Debian` and `64-bit`.
 1. Copy the install commands shown under Install and Run and run them in the console of our new LXC.
 1. Once the tunnel connects, select **Continue**.
 1. You can now setup routes to expose through your cloudflare tunnel.

 ## Disable TLS Verification
 By default, cloudflare tunnels verify TLS certificates for https routes. Some applications however require https, even if there is no valid certificate. 
 For example: the Proxmox web GUI listens on HTTPS, but without a proper certificate this cannot be verified. Hence, for some routes, we may need to disable TLS verification in our cloudflare tunnel. The steps below describe how this is done.

 1. In the [Cloudflare dashboard](https://dash.cloudflare.com/), go to **Zero Trust** > **Networks** > **Connectors** > **Cloudflare Tunnels**.
 1. Choose a tunnel and select **Edit**.
 1. Select the **Published application routes** tab.
 1. Choose an application and select **Edit**.
 1. Under **Origin request and connection settings**, set **TLS** > **No TLS Verify** to **ON**.
 1. Select **Save**.
