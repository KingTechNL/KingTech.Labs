# Web server
Some of the KingTech websites are hosted in-house, giving us full control over performance, security, and deployment.
Our web platform runs on a Raspberry Pi cluster powered by [Docker Swarm](./DockerSwarm.mdx) and GlusterFS.

Cloudflare handles DNS and routes our subdomains (for example `www.kingtech.nl`, `ggv.kingtech.nl`, and `labs.kingtech.nl`) to the right public endpoints.
To keep our network exposure minimal, we open as few router ports as possible and use a reverse proxy to route traffic internally to the correct web services.

## Traefik

Traefik is the reverse proxy that sits at the edge of our cluster and routes incoming traffic to the correct service.
It handles host-based routing, HTTPS certificates, dynamic service discovery, and natively integrates with docker. Which makes it a perfect fit for Docker Swarm deployments.

### Installation
Next thing to do, is install Traefik as our reverse proxy. For this, I took inspiration from [this blog](https://blog.antosubash.com/posts/part-2-setup-docker-swarm-with-traefik-and-portainer)

```bash
mkdir traefik
mkdir traefik/config
touch traefik/acme.json
chmod 600 traefik/acme.json
```

### Install and configure Authentik
Finally, in order to secure our web-applications, we install Authentik (see docker compose).

After installing we need to configure authentik through the Web UI. Our configuration is based on the tutorial that can be found [here](https://github.com/brokenscripts/authentik_traefik). Unfortunately this tutorial was outdated, so here is what it looks like now:

For the first time setup, we need to go to the following URL: `https://<YOUR_AUTHENTIK_DOMAIN>/if/flow/initial-setup/`. This will prompt you to create a new admin user.

After creating a new user and logging in, we will go to the `Application` page. Here we click `Add application`.
We can now setup a forward-auth flow, by filling in the following properties:

```bash
Name: Domain Wide Forward Auth Catch All
Slug: Domain Wide Forward Auth Catch All
Group: <leave empty>
Policy engine mode: Any
UI Settings: <leave default>
```

![Authentic config 1](https://res.cloudinary.com/kingtech/image/upload/q_auto/f_auto/v1775407811/authentic-config-1_ubuw9l.png)

After clicking ‘Save’ we will be redirected to create a provider.
Here we fill in the following values:

```bash
Name: Provider for Domain Wide Forward Auth
Autorizationflow: default-provider-autorization-explicit-consent
Select: Forwarding of authentication (domain level)
Authentication-URL: <YOUR_AUTHENTIC_URL>
Cookie-domain: <YOUR_ROOT_DOMAIN>
```

![Authentic config 2](https://res.cloudinary.com/kingtech/image/upload/q_auto/f_auto/v1775407813/authentic-config-2_rxv7r0.png)

Finally, we need to add the application to an outpost:
Navigate to the `outposts` tab, and edit the default `Authentik Embedded Outpost`:

![Authentic config 3](https://res.cloudinary.com/kingtech/image/upload/q_auto/f_auto/v1775407812/authentic-config-3_cyqpfv.png)

In the ‘Authentik Embedded Outpost’, select our new provider in the left list, and add it to the right list:

![Authentic config 4](https://res.cloudinary.com/kingtech/image/upload/q_auto/f_auto/v1775407811/authentic-config-4_pojfuo.png)

If all is setup correctly, we can now use authentik to protect our traefik routes.
