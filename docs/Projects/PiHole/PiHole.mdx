# PiHole

PiHole is a free DNS sinkhole that is typically used to block advertisements. It runs on a Raspberry Pi singleboard computer and in addition to blocking ad’s, PiHole can also be used as a DHCP server.

Installation of PiHole on a Raspberry Pi with Raspberry Pi OS is done using the following command (taken from the [official documentation](https://docs.pi-hole.net/main/basic-install/)).

```bash
curl -sSL https://install.pi-hole.net | bash
```

After installing PiHole, the URL your PiHole admin panel can be reached at, including a password will be shown:
Note the /admin at the end of the URL.

![PiHole installation complete](https://res.cloudinary.com/kingtech/image/upload/q_auto/f_auto/v1775413653/pihole-installation-complete_ovjaji.png)

Changing the password can be done by entering the Pi (either directly by hooking up a keyboard and monitor to it, or via SSH) and running the following command:

```bash
pihole –a -p
```

Due to PiHole logging all DNS queries in a database, we recommend setting a retention policy (max amount of time a database record exists) and/or storing the database on a separate (usb) drive. 
Raspberry Pi OS is based on Linux Debian, which has the nasty tendency to completely freeze and no longer boot once the main drive is full.

## Set a retention policy
The following commands are used to set a retention policy for the pihole database, thereby limiting its size.

First we open the pihole configuration file:

```bash
sudo nano /etc/pihole/pihole-FTL.conf
```

Next, we add a retention policy in days at the end of the file:

```bash
MAXDBDAYS=14
```

## Move the database to an (external) drive
If you really want to make sure the PiHole system is easily recoverable once the database is full, we recommend moving it to a reasonably sized (USB) drive. 
In order to do this, we need to mount the USB drive to the linux file system.
First, look up the device address in the linux system:

```bash
sudo fdisk -l
```

This will result in a list of devices, ending in something like this:

![fdisk result](https://res.cloudinary.com/kingtech/image/upload/q_auto/f_auto/v1775413651/fdisk-result_nbkd27.png)

In our case, our USB drive seems to be located at: `/dev/sda1`. 
Now, we create a directory to mount our USB drive to:

```bash
sudo mkdir /media/usb-drive
```

And mount the drive to the new directory:

```bash
sudo mount /dev/sda1 /media/usb-drive
```

:::info
The difference between `/media/` vs `/mnt/` is that `/media` is where the system mounts removable media, and `/mnt` is for you to mount things manually. Devices under `/mnt` are often not shown in (web) GUI’s, while `/media` devices are.
:::

Make pihole the owner of the new directory

```bash
chown pihole:pihole /media/usb-drive/
```

If changing the ownership of the directory is not permitted, try re-formatting the drive to use the NTFS filesystem and try again:

```bash
sudo umount /dev/sda1
sudo mkfs.ntfs /dev/sda1
sudo mount /dev/sda1 /media/usb-drive
```

Now we can configure PiHole to store its database on our USB drive. Open the the PiHole configuration file using the following command:

```bash
sudo nano /etc/pihole/pihole-FTL.conf
```

Add the following line, and exit with `CTRL-X`:

```bash
DBFILE=/media/usb-drive/pihole-FTL.db
```

Now restart pihole-FTL using the following commands:

```bash
sudo service pihole-FTL stop
sudo service pihole-FTL start
```

You should now have a new `pihole-FTL.db` file in `/media/usb-drive`.
